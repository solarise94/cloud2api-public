# API Key 权限组与 API 中转

网盘登录和存储配置由 OpenList 完成；cloud2api 只纳管存储、设置 API Key 授权和提供文件接口。管理员密码登录用于管理，API Key 用于受限的数据面文件操作，两者不能互相替代。

本文是项目维护/高级集成文档，不作为默认 Agent 提示。在线 Agent 资料只展示基础文件能力；高级接口、Gokapi 兼容中转和管理连接流程仍保留实现与原有鉴权，分层规范见 [开发接口文档](API-DEVELOPMENT.md)。隐藏说明不撤销已有权限，也不会把权限组中未授予的能力自动开放。

## 常用权限组

创建 Key 时优先选择网盘范围、默认网盘/根目录和权限组；细项放在「高级权限设置」中。

| 权限组 | 包含 | 默认不包含 |
| --- | --- | --- |
| 通用（默认） | 列表、读取/下载、写入/上传、转存、直链、URL 转存、API 中转 | 删除、彻底清理、子 Key 授权 |
| 只读 | 列表、读取/下载 | 写入、中转上传、删除、分享直链、子 Key 授权 |
| 全部 | 全部细项权限 | 无；只在确实需要时选择 |

细项对应的 API 权限是：

- 通用：`list read write transfer link fetch relay`。
- 只读：`list read`。
- 全部：`list read write delete purge transfer link fetch delegate relay`。

「全部」仍受所选网盘、根目录、限额和有效期限制，不是管理员权限。`write` 允许上传、覆盖和移动文件；「通用」不含删除并不代表写操作没有覆盖风险。直链允许生成无需 Key 即可下载的限时分享地址，故「只读」默认不额外授予直链。需要时在高级设置中显式开启。

旧 Key 的自定义权限和各盘根目录不会仅因打开编辑对话框而改成权限组。只有显式应用权限组或修改细项才改变授权。静态配置的旧权限展开规则保持兼容，不会批量重写已有 Key。

高级设置中的「全局权限」是对已授权网盘的额外授予，不是逐盘限制：有效权限为全局权限与该盘权限的并集。只取消某个网盘的勾选项，不能撤销仍在全局权限中开启的同一权限；需要一并取消全局项。全局权限不会自动授权未勾选的网盘，也不会绕过根目录。

## 单盘、跨盘和默认根目录

- **单个网盘**：只授权一个具体网盘，它也是默认网盘。
- **跨网盘**：明确勾选当前已纳管的网盘，权限组应用于所选范围；必须从所选网盘中指定默认网盘。之后新纳管的网盘不会自动获得授权。
- **根目录**：默认 `/` 表示该 OpenList 存储的根目录；可填写 `/某个目录` 将该 Key 限制在存储内的子目录。它不是宿主机路径，也不是多个网盘合并后的虚拟根目录。
- **默认位置**：不写 drive 的 `/v1/files`、`/v1/list` 等简短调用定位到默认网盘，并受它的 Key 根目录约束。跨盘调用仍需明确源盘和目标盘，并分别校验读取/写入权限。
- **高级根目录**：每个所选网盘可以有自己的限制目录。切换默认网盘不应把其他网盘的根目录清空或扩大。

纳管网盘本身不会给任何现有 Key 增加授权。权限调整只由管理员编辑 Key 完成，不再提供 agent 权限申请或审批模块。`/v1/requests` 和管理端审批接口已经移除；保留的旧审批数据不再参与运行时授权。

## API 中转登录

`/relay/` 是独立、未与门户互链的本地「中转上传工具」页面：门户内没有指向它的入口，管理登录页也不再提供「API 中转登录」标签；需要时直接在浏览器打开该地址。页面明确标注为中转工具，只提供上传、自己的文件列表、回执查询和下载分享，不含网盘管理、权限调整或查看其他 Key 的能力。

Key 只保留在当前页面的内存里，通过 `apikey` 请求头发送；不写入 URL、浏览器本地存储或 Cookie。刷新页面或退出后需重新输入。使用远程部署时建议 HTTPS；普通 HTTP 局域网连接不能防止链路上的窃听。

中转页显示 Key 的实际中转目标、范围和能力，并复用现有 Gokapi 兼容上传接口。中转权限不会绕过根目录、上传大小、配额、存储身份或有效期检查。文件仍存放在 OpenList 连接的存储上，不是第二个网盘登录服务；它也不会把请求转发给远端 Gokapi 服务——API 上游存储（`goapi`，connect 4）只通过 `/v1` 分层接口访问，Gokapi 扁平上传 API 不作为上游协议。

## 模型如何确认上传结果

Gokapi 兼容接口继续保留原有字段，并增加可查询的上传结果。分块暂存成功、HTTP 请求体发送完毕、浏览器进度到 100% 都不等于远端文件上传完成。

上传调用可以携带客户端生成的随机 ID：

```text
X-Upload-ID: <随机上传 ID>
```

服务端返回上传 ID，并在接收文件、请求中断和上游响应后记录结果。使用同一 Key 查询：

```text
GET /api/files/status/<上传 ID>
apikey: <API Key>
```

状态字段 `Status` 的含义：

- `uploading`：仍在接收、提交或等待上游；模型不能宣称完成。
- `completed`：上游上传已确认成功，cloud2api 的文件元数据也已保存；可报告文件信息和校验值。
- `failed`：收到明确的校验、限额、上游或元数据保存错误；模型应说明失败原因，不隐藏非阻塞上传的后台错误。失败不保证远端没有文件，尤其是上游已接收但校验或本地元数据保存失败时；不能据此宣称已经回滚。
- `interrupted`：请求断开、取消或服务中断，结果可能不完整；远端可能已有部分或完整文件，不能宣称已经回滚或不存在。

客户端断线时无法在断开的连接上收到最终响应，应使用已知上传 ID 在重新连接后查询。查询没有结果或超时只能报告「结果未确认」，不能推断上传成功，也不能据此断言远端没有文件。上传状态只允许原 Key 查询，不因知道 ID 而对其他 Key 开放。

模型应把终态、上传 ID、文件信息或错误原因返回给使用者。非阻塞上传先返回 `uploading` 时，须等待后续查询得到终态；不要把“开始处理”写成“上传完成”。重试前先查询原尝试的结果，避免重复提交或覆盖。`X-Upload-ID` 是一次尝试的身份，新的直接上传或重试必须生成新 ID；复用旧 ID 提交另一份请求返回 409，不会覆盖原回执。分块暂存可以沿用同一 UUID/上传 ID，提交完成阶段只允许一次工作者取得提交权。
