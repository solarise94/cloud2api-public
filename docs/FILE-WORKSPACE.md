# 我的文件：人用网盘工作台

## 入口与使用

工作台位于 `/files/`，启用管理门户时，访问实例根地址 `/` 也会跳转到这里。管理门户侧栏和 Key 创建、轮换、使用弹窗提供入口；`/admin/` 继续用于存储纳管、授权与实例管理。

1. 输入**本实例签发**的 API Key。网盘账号密码、OpenList 密码、上游 GoAPI Key 不填在这里。
2. 此 Key 仅授权一个网盘时，登录后直接进入该盘的授权根目录；授权多个网盘时，先显示「我的网盘」供选择，默认盘只做标记。没有网盘授权时显示空状态，不猜测或扩大授权；单盘缺少 list 权限时仍明确说明无法浏览。
3. 点击一个网盘进入「上传与分享」页：大面积拖放上传区在前，文件管理默认展开，也可手动收起；每次进入网盘都会重新展开。面包屑中的根目录是 Key 对该盘的授权根，不是 OpenList 的挂载路径。文件列表按服务端分页；筛选只作用于当前页。
4. 选择或拖入文件到当前目录。切换目录时，路径导航与上传目标提示同步更新；目录加载中或失败时不沿用旧目录的文件统计。上传队列固定选入文件时的目标网盘和目录，切换目录不会把进行中的任务改投到另一个位置。重名默认拒绝，不自动覆盖。
5. 上传完成后，上传记录中的任务提供醒目的「获取链接」按钮：点击打开分享对话框，选择有效期并确认「生成链接」后才创建公开下载链接（也可在文件管理中对该文件「分享」）。上传本身绝不自动公开文件；接收人凭链接下载，无需 API Key。

「我的」表示当前 Key 的授权范围，不是新增了多用户注册、个人密码、用户配额或独立账号体系。不自动创建或扩大任何 Key，也不把管理员登录当作文件访问授权。Key 明文丢失时仍须管理员轮换，工作台不能恢复它。

## 权限与操作

| 操作 | 所需权限 |
| --- | --- |
| 查看目录、进入文件夹 | list |
| 下载文件 | read |
| 上传、创建目录、重命名 | write |
| 删除 | delete |
| 创建公开下载链接 | link |

有效权限为当前 Key 的全局权限与**已授权网盘**的逐盘权限的并集；全局权限不会使一个未授权网盘自动可见。前端禁用按钮只是交互反馈，服务端每次操作仍验证 Key、根目录、限额、网盘身份及相应权限。不要通过给日常 Key 选择「全部」来绕过某个按钮禁用。

通用 Key 不含 delete，但 write 仍可重命名、移动或按明确冲突策略覆盖，不能把它理解为无破坏性权限。删除需显式确认，结果按服务端逐项状态显示；是否进入回收站取决于现有 Key 策略，不能保证任意网盘可恢复。工作台不提供 purge。

## 上传与下载结果

上传使用现有指定盘文件接口，原始文件流直接发往网关；空文件使用 multipart 避开原始请求体需要正 Content-Length 的限制。浏览器发送进度到 100% 后显示等待确认，而不是立即显示完成。只有有效的上游确认响应、目标路径、大小与校验字段符合约定后，才标记完成。

断网、取消或缺少有效确认时显示中断／结果未确认；远端可能已写入，不能据此自动重试、覆盖或声称回滚。队列不会因刷新页面而持久化，退出会清理内存并取消本页请求。客户端取消只是停止等待或发送，无法撤销上游已完成的写入。

下载先用 Key 请求头申请**短时、限定单文件的下载凭证**，再由浏览器原生下载器接收服务器流式响应。网页不收集完整文件、不生成 Blob，不再依赖 File System Access API、HTTPS 安全上下文或浏览器的本地文件选择器；大文件不再因这条前端路径占用整文件内存。API Key 不进入下载 URL，也不会为普通下载创建公开分享链接。

页面只提示「已交由浏览器下载」，不能据此宣称下载或本地保存已完成。进度、取消、失败与实际完成状态由浏览器下载列表管理；退出工作台会取消尚未完成的凭证申请，但不能取消已经交给浏览器的下载。下载凭证本身在短暂有效期内也具有持有者访问能力，请勿转发；长期或主动分享仍使用独立的「分享」操作。

## 公开分享

- 点击「获取链接」（上传记录中已完成的任务）或文件管理里的「分享」只会打开对话框；在对话框内确认「生成链接」后才调用 `POST /v1/links`，上传不会自动公开文件。没有 link 权限时，上传区会明确说明无法生成公开链接。
- 可选有效期不超过 7 天，使用服务器返回的公开地址和到期时间。
- 链接具有持有者访问能力，知道链接的人即可下载。发送前确认文件允许公开，勿将链接当作私密认证。
- 链接到期不会删除原文件；文件被移动、删除，Key 被撤销或过期，以及网盘不可用均可能导致下载失效。
- 原生链接目前不提供密码、下载次数上限、访问统计或逐条撤销 UI。不要把 Gokapi 临时中继的次数与保留策略套到原网盘链接上。
- 分享 URL 取决于实例的公开访问地址设置。发给外部人员前，应由管理员正确配置公开地址、反向代理和 HTTPS；页面不会替管理员开放端口或修改网络。

## 安全边界与实现

工作台不新增文件操作后门或管理员代理。普通操作沿用 API Key 数据面；原生下载另用短时单文件凭证，将原 Key 的既有 read 授权交给浏览器下载器使用，不产生独立或更大的文件授权。

- `/files/` 与白名单资源无需会话，响应设置 no-store、严格 CSP、nosniff、no-referrer；不设置管理员 Cookie。
- API Key 只在页面模块内存中，通过 `apikey` 请求头发送；不放 URL、Cookie、localStorage 或 sessionStorage。fetch 请求使用 `credentials: omit`；上传 XHR 不启用跨域凭据。浏览器的同源 XHR 不能用该选项排除所有 Cookie，但本项目管理员 Cookie 的 Path 限于 `/admin`，不会随 `/v1` 文件请求发送，文件 API 也不以 Cookie 授权。
- 退出、认证失效和页面离开会清除状态、取消本页管理的请求；异步响应按登录与目录代次检查，不能将上一个 Key 的列表、分享结果或迟到的下载凭证用于下一个 Key。已经交给浏览器下载器的任务由浏览器继续管理。
- 下载凭证绑定 Key、网盘、单文件、授权根与存储身份，约 120 秒有效，可在有效期内重试或 Range 下载。每次兑换重查当前 Key 与 read 授权，不允许凭旧凭证绕过撤销、到期或授权变化。有效流不会在 120 秒时被主动切断；凭证不依赖进程内存，重启后仍以同一持久签名密钥验签，轮换签名密钥会使旧凭证失效。不要在反向代理访问日志中记录完整凭证 URL。
- 文件名、路径、错误等均按文本展示，不把网盘内容作为 HTML 或脚本运行。
- `cloud2api only links to the patch pages; it never receives credentials or writes storage config.` 此处指网盘与上游存储的登录凭据和配置；工作台依职责处理自身的数据面 API Key。
- `/relay/` 保留独立临时投递箱用途，不迁移或删除其兼容路由。工作台不接入其隐藏 `.relay` 目录。
- 不加入相册、媒体／Office 预览、用户注册或 OpenAI 模型协议，不改变 Agent 基础层接口发现清单。

入口与静态资源：`internal/admin/files.go`、`web/files.html`、`web/assets/files.js`、`files.css`；公共视觉令牌沿用 `app.css`。文件数据仍由 `internal/agentapi` 的既有 `/v1` 处理。

## 开发验证

`/files/?mock=1` 使用独立的内存演示数据。网盘、文件、上传和分享均不调用真实数据面；退出或刷新后不保留演示修改。不要将演示中的链接或完成状态当作真实网盘测试证据。

```sh
go test ./internal/admin ./internal/agentapi
node scripts/test-files-page.cjs
node scripts/test-agent-onboarding.cjs
```

端到端验收只在隔离的模拟／Local 存储中进行。不得对用户真实网盘运行写入型自检、删除测试、故障注入或重建夹具。部署仍须单独做当前库存检查、一致性备份与回滚准备。
